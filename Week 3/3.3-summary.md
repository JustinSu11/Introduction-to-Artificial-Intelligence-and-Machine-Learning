# 3.3 Intro to Machine Learning and Supervised Learning
*AAI-501 · Week 3 · cross-checked against the transcript*

**One line:** When you have **data but not the rules**, machine
learning learns the pattern. **Supervised learning** predicts a
known target, and you grade it with the **right metric** for
regression or classification.

**Hook:** Search and optimization know the rules of the world.
ML only sees the **results** of the rules and works backward.

## Why ML
- **Search (Module 2):** world fully observable, actions
  deterministic, outcomes known.
- **Optimization (3.1):** we know the rules (5 wood + labor
  makes a table).
- **Real world:** often you have only **observations**, the
  *outcomes* of how the world works, not the rules. -> ML.

## What is ML (two views)
1. **Agent view:** a field of AI about an agent **improving its
   behavior from experience** (often embodied AI: robots in a
   maze, delivery robots).
2. **Algorithm view:** algorithms that **learn patterns from
   data and predict without being explicitly programmed for
   every task** (e.g., a regression in a Jupyter notebook).
- **Combined:** the science of teaching computers to **learn
  from experience and improve at a task over time.**

## 3 flavors
| Type | Goal | Graded? | Examples |
|---|---|---|---|
| **Supervised** | Predict a **target** from data | **Yes**, there's a correct answer | Home sale price, dog vs cat image, customer purchase, medical diagnosis, credit scoring, speech recognition, spam detection |
| **Unsupervised** | Find **patterns**, no right answer | No | **Clustering**, **anomaly detection**, topic modeling, customer segmentation, gene expression analysis, image compression |
| **Reinforcement (RL)** | Learn good **behavior from the environment** by trial and reward | By reward over time | Boston Dynamics robot dogs (learning to walk), **AlphaGo**, self-driving cars, dynamic pricing (Uber/Lyft), personalized education, ad placement, video-game NPCs |
- **Why RL for AlphaGo:** you can't just label "win/not win."
  It plays thousands to millions of games to learn strategy.
- **Anomaly detection** is unsupervised: how different is
  "different enough?"
- This week = **supervised.**

## 3 things every supervised task needs
1. **The task:** be crisp. "Predict home price" could mean the
   **dollar amount** or **above/below list price.**
2. **The data:** what you have (and **don't** have). Use
   **exploratory data analysis.**
3. **A performance measure** (loss function): how do you know
   you're improving?

## Classification vs regression
- **Classification:** predict **categories** (dog/cat, read/skip a
  message-board post).
- **Regression:** predict **numbers** (house price from square
  footage).

### Terminology
| Term | Meaning |
|---|---|
| **Input features** | Data you give the model |
| **Target feature** | What you want to predict |
| **Predictor** | The model: takes new input features, outputs a prediction |

## Two foundation models (from AAI-500)
**Linear regression**
- Fit a line: **Y = B0 + B1 X** (intercept + coefficient).
- Estimate parameters **B0-hat, B1-hat** from data.
- **Residuals** show how far off we are.
- Important because many fancy methods are **generalizations
  or extensions** of it.

**Logistic regression**
- Put the linear term **through a sigmoid** -> output is a
  **probability (0 to 1).**
- Builds a **decision boundary.** **>= 0.5 -> one class**
  (e.g., repay), **< 0.5 -> the other** (e.g., default).
- Example: features income and employment duration -> default
  or repay.

## Regression metrics
| Metric | Formula idea | Use when |
|---|---|---|
| **MSE** (mean squared error) | Average of **(actual - predicted)^2** | You want to **penalize large errors heavily** |
| **MAE** (mean absolute error) | Average of **\|actual - predicted\|** | All errors count **equally** (linear impact) |
| **MAPE** (mean absolute % error) | Average of **\|actual - predicted\| / actual** | You want error as a **percentage** |
| **R-squared** | **1 - SSR / SST** | You want how much **variance** the model explains vs a baseline (predicting the mean) |

- **SST** = total variance: sum of (observation - mean)^2.
- **SSR** = variance left over (sum of squared residuals).
- **R-squared example:** if SSR/SST = 0.1 (10% unexplained),
  **R-squared = 0.9.** Better model -> smaller SSR/SST -> bigger
  R-squared.
- **R-squared** for: "how much better than just predicting the
  mean?", comparing models **on the same dataset**, fields like
  **economics and healthcare** that expect a goodness-of-fit.
- **MSE / MAE / MAPE** for: **error magnitude**, which matters
  in business ("is the forecast +/-15% of revenue?", "house
  price within +/-$150,000?").
- *(Lecture says MAPE is between 0 and 1. In practice it can
  exceed 1. Use the lecture's claim on a quiz.)*

## Classification metrics
Positive = class 1, negative = class 0.
| | Actually positive | Actually negative |
|---|---|---|
| **Predicted positive** | **TP** (true positive) | **FP** (false positive) = **Type I error** |
| **Predicted negative** | **FN** (false negative) = **Type II error** | **TN** (true negative) |

**Not all errors cost the same:**
- **Cost of FP high:** **spam filter.** Marking an important
  business email as spam is worse than letting some spam
  through.
- **Cost of FN high:** **early disease screening.** Missing
  a life-threatening disease is worse than an extra follow-up
  test.

| Metric | Formula | Cares about |
|---|---|---|
| **Accuracy** | (TP + TN) / all | Overall correct. Doesn't separate FP from FN |
| **Precision** | TP / (TP + FP) | **False positives.** "When I say positive, am I right?" |
| **Recall** | TP / (TP + FN) | **False negatives.** "Did I catch the positives?" |
| **F1** | **Harmonic mean:** 2 x P x R / (P + R) | Balance of both |
- *(Lecture describes F1 as "multiply in the numerator, add in
  the denominator"; the full formula includes the factor 2.)*
- **F1 example:** **information retrieval.** Avoid irrelevant
  pages (precision) and don't miss relevant ones (recall).
- Python packages print the **whole suite** by default.

## ROC and AUC (all thresholds at once)
- Default threshold is 0.5, but it **can move with business
  conditions:**
  - Lender: good economy -> **lower** cutoff (e.g., 0.3);
    bad economy -> **stricter** (e.g., 0.7).
  - Medical tests: disease frequency changes (pandemic) -> you
    may shift the boundary.
- **ROC curve:** **x = false-positive rate, y = true-positive
  rate**, one point per threshold.
- **Strict threshold (e.g., 0.85):** little gets through -> **both
  TPR and FPR low.** A good model still has TPR > FPR.
- **Lenient threshold (e.g., 0.15):** everything gets through ->
  both high.
- Sliding the threshold from strict to lenient traces the
  curve. A **good model gains true positives faster than false
  positives** -> curve goes **up and to the left.**
- **Random classifier** (coin flip) = diagonal line.
- **Perfect classifier:** jumps straight up (TPR 1, FPR 0).
- **AUC** (area under the ROC curve): **0.5 = random, 1.0 =
  perfect.** (Lecture: values between 0.5 and 1.) Measures
  **overall classifier quality, not one threshold.**
