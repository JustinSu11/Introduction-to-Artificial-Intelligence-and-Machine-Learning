# 3.1 Mathematical Optimization
*AAI-501 · Week 3 · cross-checked against the transcript*

**One line:** When the world has **limits** (hours, wood, shelf
space, power), you write the problem as **equations and
inequalities** and solve for the best answer. The best answer
sits at a **corner** of the feasible region.

**Hook:** Fence in the land (constraints), then slide the
profit line to the farthest corner you can still touch.

## Why it matters
- Agents must decide **under constraints**, not with free reign.
- Lecturer's claim: the **most under-taught** topic in AI and
  data science, yet it appears at every company.
- Also called **mathematical programming.**
- **Examples of constrained problems:**
  - **Manufacturing:** how many of each product, given (say)
    100,000 person-hours/year and limited materials.
  - **SKU rationalization (retail):** which products go on the
    shelf, and which shelf (eye level vs bottom), given limited
    shelf space.
  - **Power grid balancing:** send power where needed without
    exceeding capacity in each area.

## 3 flavors
| Type | Variables | Example from lecture |
|---|---|---|
| **Linear programming (LP)** | **Continuous** only | Oil refinery makes gallons of X1 and X2: **5X1 + 20X2 <= 400** person-hours, **X1, X2 >= 0** |
| **Mixed-integer programming (MIP)** | Can be **integer or Boolean** (adds logic) | Build stores (X1) and distribution centers (X2): **X1 + X2 <= 5**, both **integers**, no 3.5 stores |
| **Quadratic programming (QP)** | **Non-linear** terms (squares, X1*X2) | Ad impact grows like a **square root** of spend (diminishing returns). Stock portfolios with dividends and compounding |

## The factory problem (running example)
501 bot runs a factory making **chairs (X1)** and **tables (X2)**.
| | Mahogany | Labor hours | Price |
|---|---|---|---|
| **Chair** | 5 | 10 | **$45** |
| **Table** | 20 | 15 | **$80** |
| **Weekly capacity** | **400** | **450** | |

**Goal:** the mix of chairs and tables that **maximizes revenue.**

**Model:**
- **Objective:** maximize **Revenue = 45 X1 + 80 X2**
- **Mahogany:** 5 X1 + 20 X2 <= 400
- **Labor:** 10 X1 + 15 X2 <= 450
- **Non-negativity:** X1, X2 >= 0 (no negative chairs)

### Terminology (know these)
| Term | Meaning here |
|---|---|
| **Resources** | Mahogany, labor |
| **Products** | Chairs, tables |
| **Parameters** | Fixed inputs: prices, resource capacities, **technology coefficients** (how much of each resource one product needs) |
| **Decision variables** | What we choose: X1, X2 |
| **Constraints** | Mahogany limit, labor limit |
| **Objective function** | What we maximize: weekly revenue |

Parameters are **treated as fixed**; we don't optimize them.

## Feasible region (the "fence")
- Plot each constraint as a line. The shape they enclose is the
  **feasible region** (a **polyhedron**): every plan you can
  actually build.
- **Labor line** 10X1 + 15X2 = 450: **45 chairs** or **30 tables**
  if labor were the only limit.
- **Mahogany line** 5X1 + 20X2 = 400: **80 chairs** or **20
  tables** if wood were the only limit.
- **All constraints apply at once.** 30 tables is impossible:
  30 x 20 = **600** mahogany > 400.

## Revenue line (the "sliding ruler")
- Set revenue = a number, e.g. $0: 45X1 + 80X2 = 0 draws a line.
  **Every point on it earns the same revenue.**
- Its **slope never changes**: it is the **ratio of the two
  prices.** Only the **dollar level** changes.
- **Method:** push the line toward higher revenue **as far as it
  can go while still touching the feasible region.**
  - Reaches **(0, 20)** (all tables): **$1,600.** Not far enough.
  - Last touch at **24 chairs, 14 tables: $2,200.** Best.
- Same idea as **gradient ascent** (follow the direction that
  raises the objective).
- Check: 5(24) + 20(14) = 400 and 10(24) + 15(14) = 450. Both
  constraints are used up exactly. 45(24) + 80(14) = **2,200.**

## Fundamental theorem of linear programming
> If an LP has an optimal solution, **at least one optimal
> solution is a corner point (vertex)** of the feasible region.

*(Transcript garbles it as "only one point"; the theorem says
at least one, since ties are possible along an edge.)*

- The factory has **4 vertices:** (0,0), (0,20), (45,0), and the
  optimum **(24,14).**
- **Not a special case of these prices.** Change the prices and
  the revenue line tilts (the lecture's example: chairs worth
  more -> line slopes differently), but the farthest touch is
  **still a vertex.**
- So: **solve an LP by finding the right vertex.**

## The scaling problem (why we need something smarter)
| Problem size | Vertices to check |
|---|---|
| **10 variables, 10 constraints** | just under **185,000** (C(20,10) = 184,756) |
| **500 variables, 500 constraints** (still "small") | about **10^299** |
- For comparison, the lecture says about **10^88 atoms** in the
  universe. (Commonly cited figure is nearer 10^80. Use the
  lecture's number on a quiz, same conclusion.)
- **Brute force is intractable.**
- **Answer:** **George Dantzig's simplex algorithm** (next
  lecture, 3.2).

though you can't build 1.5 tables. That keeps it an LP. Forcing
integers would make it MIP.)*
