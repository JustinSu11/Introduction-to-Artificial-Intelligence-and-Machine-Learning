# 3.2 The Simplex Algorithm
*AAI-501 · Week 3 · cross-checked against the transcript*

**One line:** Simplex **walks from vertex to vertex**, always
improving revenue, instead of checking them all. Each step:
**one variable enters, one leaves.**

**Hook:** Climb the hill by corners. Take the **steepest uphill**
step (largest reduced cost), but **stop before you fall off the
fence** (minimum ratio test). Done when every direction is
downhill.

## Why simplex
- 10 vars/10 constraints = ~185,000 vertices. 500/500 = 10^299.
  Brute force is impossible.
- **George Dantzig** (decades ago) built simplex. It is the
  **fundamental algorithm** of mathematical optimization.
- Lecturer: the terminology is a barrier (standard form,
  canonical form, non-basic variable, reduced cost, entering
  the basis, pivoting). The lecture turns it into **5 plain
  steps.**

## Step 1: Standard form (remove inequalities)
- Add a **slack variable** to each constraint to soak up
  leftover resource and make it an **equation.**
  - 5X1 + 20X2 **+ h1 = 400**
  - 10X1 + 15X2 **+ h2 = 450**
- **Slack = unused resource.**
  - If 5X1 + 20X2 = 380 -> **h1 = 20** (380 + 20 = 400).
  - If 10X1 + 15X2 = 400 -> **h2 = 50** (400 + 50 = 450).
- "Converting to standard form" means exactly this.

## Key insight: zeros and non-zeros encode a vertex
- Variables now: **x1, x2, h1, h2.**
- At **every vertex, the same number of variables are zero**
  (the lecture: "the ratio of zero to non-zero stays constant").
- **Origin (0,0):** x1 = 0, x2 = 0; h1 = 400, h2 = 450 are
  non-zero -> encoding **0, 0, 1, 1.**
- **Vertex (0,20)** (all tables, wood used up): x1 = 0, **h1 = 0**;
  x2 and h2 non-zero -> encoding **0, 1, 0, 1.**
- Simplex is just **searching for the right zero/non-zero
  pattern**, which maps to the optimal vertex.

## Vocabulary
| Term | Meaning |
|---|---|
| **Basic variable** | Allowed to be **non-zero** (in the basis) |
| **Non-basic variable** | Currently **set to zero** |
| **Basic feasible solution** | A feasible vertex with some basic and some non-basic variables. Doesn't have to be good |
| **Enters the basis** | Goes zero -> non-zero |
| **Leaves the basis** | Goes non-zero -> zero |
| **Pivoting** | One round: one variable in, one out |
| **Reduced cost** | The variable's coefficient in the objective: how fast revenue rises if it enters |
| **Canonical form** | Basic variables on the left, written as functions of the non-basic on the right |

## The 5 steps (as taught)
1. **Standard form:** add slacks.
2. **Start at an easy basic feasible solution:** the **origin.**
3. **Canonical form:** write basics (h1, h2) in terms of
   non-basics (x1, x2).
4. **Entering variable:** pick the non-basic with the
   **largest (positive) reduced cost.** Greedy.
5. **Leaving variable:** **minimum ratio test.** Pivot, rewrite
   in canonical form, **repeat** until no non-basic variable has
   a positive coefficient.

## Worked example (factory)
**Round 0, at the origin (x1 = x2 = 0):**
- h1 = 400 - 5x1 - 20x2
- h2 = 450 - 10x1 - 15x2
- Revenue = 45x1 + 80x2 + 0h1 + 0h2

**Round 1:**
- **Enter:** x2 ($80 > $45, largest reduced cost). *Greedy*, like
  greedy best-first search.
- **Leave (min ratio test):** how many tables before something
  runs out?
  - Wood: 400 / 20 = **20 tables**
  - Labor: 450 / 15 = **30 tables**
  - **Smaller wins -> mahogany runs out first -> h1 leaves.**
- Pivot to (0, 20). Rewrite:
  - x2 = 20 - (1/4)x1 - (1/20)h1
  - Revenue = **1,600 + 25x1 + 0x2 - 4h1 + 0h2**
  - h2 = 150 - (25/4)x1 + (3/4)h1

**Round 2:**
- Non-basics now: x1 (reduced cost **+25**), h1 (**-4**).
  **x1 enters.**
- Min ratio test:
  - x2 row: 20 / (1/4) = **80**
  - h2 row: 150 / (25/4) = **24**
  - **24 is smaller -> h2 leaves.**
- (The lecture notes intuition "breaks down" here. Trust the
  steps.)
- New vertex (24, 14). Revenue = **2,200 + 0x1 + 0x2 - h1 - 4h2.**

**Stop:** the non-basics (h1, h2) have **negative**
coefficients, so raising either one only lowers revenue.
**Optimum = $2,200** after **2 pivots.**

*(Do not confuse "minimum ratio test" with picking the
largest. Entering = largest reduced cost. Leaving = smallest
ratio.)*

## Stopping rule
- A variable can enter only with a **positive** coefficient.
- **All non-basic coefficients negative (<= 0) -> optimal.**

## Why simplex matters beyond LP
- **Heuristics for harder search:** recall informed search needs
  an **admissible heuristic** (estimate <= true cost, e.g.
  straight-line distance from the San Diego Farmer's Market to
  the Civic Theater). A standard way to get one is to **solve a
  simpler, relaxed version.**
  - **MIP -> relax the integer rule** (allow 3.5 distribution
    centers) -> becomes an LP -> simplex solves it -> gives a
    bound/heuristic.
- **Column generation:** solve huge LPs with many variables when
  only a few matter (sparse).
- **Decomposition methods:** break huge problems into smaller
  chunks.
- **Sensitivity analysis:** how the answer changes when
  parameters change.
- Lecturer: simplex is the **gateway** to the field.
