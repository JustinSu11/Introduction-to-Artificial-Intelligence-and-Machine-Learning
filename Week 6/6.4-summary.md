# 6.4 Overfitting and Transfer Learning
*AAI-501 · Week 6 · cross-checked against the transcript*

**One line:** Deep nets have **more parameters than data,** so they
memorize. Fixes: **SGD, slow learning rate, L2, dropout, batch
norm, early stopping, data augmentation.** And **transfer
learning** reuses a pretrained model so you don't start from zero.

**Where it fits:** 6.1-6.3 built networks. 6.4 makes them
**generalize.**

---
# LAYER 1: LEARN IT

## The big idea
**Overfitting** = near-perfect training loss, but **validation loss
spikes up.** The model memorized, it didn't learn the rule.

**Hook:** a student who **memorizes the answer key** and fails
the real exam.

## Fix 1-2: SGD and slow learning rate
- **Stochastic / mini-batch GD:** fit on **small chunks,**
  iteratively.
- **Slower learning rate:** careful, steady steps.

## Fix 3: Regularization (L2)
Add a penalty to the loss: **loss + (lambda x sum of squared
weights).** Bigger weights = bigger loss, so training keeps
weights small.
Tiny example (verified, lambda = 0.1):
| Weights | Penalty |
|---|---|
| [2, -1] | 0.1 x (4 + 1) = **0.5** |
| [4, -1] | 0.1 x (16 + 1) = **1.7** |
Doubling one weight raised the penalty a lot.
In backprop it just **adds one extra term** to each gradient
(proportional to the weight).
*My addition: lambda is the "penalty strength" knob; the lecture
shows the idea without naming it.*

## Fix 4: Dropout
**Randomly turn off neurons** each training round.
- Math: a **Bernoulli** (probability p on/off) mask is applied
  **element-wise** to the weighted terms.
- **Problem it solves: co-adaptation.** One neuron learns a good
  feature, the others **lean on it,** the network becomes
  **brittle** (that feature could be a quirk of the data).
- With dropout any neuron can vanish, so **everyone must learn
  something useful.** Stronger, more general networks.

**Hook:** a **team project** where the star might be absent on any
day, so everyone learns the whole job.

## Fix 5: Batch normalization
Re-normalize (**mean and variance**) **between layers,** usually
**after the linear step, before the activation.**
Two benefits:
1. Stops **covariate shift** (values drifting away from a
   normalized range), which causes unstable training (gradients
   that **explode or vanish**).
2. Adds a **little noise,** which helps robustness.
First proposed **2015.** Works in CNNs too (conv, batch norm,
conv...).

## Fix 6: Early stopping
Plot **error vs epochs** for training and validation. **Stop when
validation stops improving** (it plateaus or rises) even though
training keeps improving.
(From 6.6: the lab's curves suggest stopping near epoch 6.)

## Fix 7: Data augmentation (images)
**Problem:** a cat training set that is all upright cats learns
"ears above eyes above nose." Simulate **other configurations.**
| Option | Does |
|---|---|
| **Rotation range** | rotate randomly |
| **Width / height shift** | move left-right / up-down |
| **Brightness** | change light |
| **Shear range** | stretch and slant |
| **Zoom range** | zoom in/out |
| **Horizontal / vertical flip** | mirror |
**Fill mode** for new pixels: **nearest** (stretch last pixel),
**reflect** (mirror), **wrap** (take from other side),
**constant** (e.g. gray).

### Offline vs online
| | Offline | Online (on the fly) |
|---|---|---|
| When | augment **once** before training (100k -> 1M images) | **new** augmentation **each epoch** |
| Cost | **cheaper** | **more expensive** |
| Robustness | less | **more** (more common) |

## Transfer learning
**Problem:** building a state-of-the-art CNN (**VGG,** **ResNet**)
from scratch is hard, and needs huge data and compute.
**Idea:** all image models share the **same basic features**
(lines, circles, curves). Reuse the **feature identifier,** retrain
only the **classifier.** Example: car classifier -> **golf cart**
classifier.

**Hook:** hire an **experienced chef** and teach only the new
menu.

**How common?** Lecture: **80-85% of industrial deep learning
models** are transfer learning (e.g. from **Hugging Face**).
**Three reasons:**
1. You can't out-design **BERT, GPT, VGG** (billions in capital).
2. Scratch training needs **lots of data and compute.**
3. Scratch takes **long;** industry wants fast **time to market.**
Used for text, image classification, even time series.

### Four steps
1. **Choose a base model** (VGG, ResNet families).
2. **Fine-tune or not?** Fine-tuning the feature identifier needs
   **more time and data** but may be better; otherwise train only
   the classifier.
3. **Prepare data** and pick augmentation (**offline vs online**).
4. **Train** the classifier (and/or feature identifier).

### Augmentation choice in transfer learning
Frozen feature identifier still costs time (forward passes through
many layers).
- **Offline:** **one** pass through the frozen part: **fast, less
  generalization.**
- **Online:** **many** passes: **slower, generalizes better.**

## Big picture recap
- Overfit = train good, validation bad.
- Fixes: small batches, slow LR, **L2, dropout, batch norm, early
  stopping, augmentation.**
- Transfer learning = **reuse features, retrain the classifier.**
- Offline = cheap, online = robust.

# LAYER 2: QUIZ REFERENCE

- Overfitting symptom: low training loss, **validation loss spikes
  up.** Often **parameters > data points.**
- Three common approaches: **stochastic gradient descent, slower
  learning rate, regularization.**
- Regularization: add **squared sum of all model weights** to the
  loss; keeps weights small; adds a term to the backprop gradient.
- **Dropout:** randomly disconnect neurons; **Bernoulli**
  distribution with probability p; element-wise; avoids
  **co-adaptation**; forces generalization.
- **Batch normalization:** recompute mean and variance at each
  layer; after linear transformation, before activation; fixes
  **covariate shift,** adds noise; proposed **2015.**
- **Early stopping:** stop when validation stops improving.
- **Data augmentation:** rotate, width shift, height shift,
  brightness, **shear** range, **zoom** range, horizontal flip,
  vertical flip. Fill modes: nearest, reflect, wrap, constant.
- **Offline** augmentation (10 new images from 100,000 -> 1M) vs
  **online** (new augmentation each epoch).
- **Transfer learning:** maximize reuse of what exists.
  Base models: **VGG** (Visual Geometry Group), **ResNet**
  (branching). 80-85% of industrial models.
- Reasons: can't beat BERT/GPT/VGG, data and compute scarce, time
  to market.
- Four steps (above). Fine-tune = more time and data.
- Offline = faster, less general. Online = slower, more robust.
