# 6.5 RNNs (Recurrent Neural Networks)
*AAI-501 · Week 6 · cross-checked against the transcript*

**One line:** An **RNN** processes **sequences** (words, audio, time
series) by feeding each step's **hidden state** into the next step,
so the past carries forward. Plain RNNs **forget** over long
distances, so **GRU / LSTM** add **gates** to choose what to keep.

**Where it fits:** CNNs handle space (images). RNNs handle **time /
order.** Transformers (future courses) have mostly replaced them.

# LAYER 1: LEARN IT

## The big idea
In **sequence data** the order matters: previous points influence
later ones. Examples: **written language, audio** (speech to text,
e.g. Whisper), **time series** (anti-diabetic drug sales in
Australia).

**Hook:** reading a sentence. You understand each word using the
**memory** of the words before it.

## 1) The N x T x D shape
| Letter | Meaning | Commute example | Stock example |
|---|---|---|---|
| **N** | number of **samples** | number of trips | number of **windows** (10-day boxes) |
| **T** | **time steps** | minutes in a trip | days in each window (10) |
| **D** | **features** | latitude, longitude (also speed, satisfaction) | stock prices: D = 1 for one stock, **4 for four stocks** |

### Different lengths: pad
RNNs expect equal-length sequences, so **pad** short ones with
**zeros/nulls.** Example reviews: "I like artificial
intelligence." / "The class was okay, but honestly not my absolute
favorite." / "A plus." Other tricks (later courses): reduce to
roots, remove stop words.

## 2) The recurrent idea (step by step)
Normal one-hidden-layer net: input -> hidden **h** -> output.
**The twist:** make **h(t)** depend on **itself one step back.**
**h(t) = activation( W·x(t) + U·h(t-1) + b )**, then
**y(t) = activation( V·h(t) )**.
- Start with a random/made-up **h0.**
- *My addition: W, U, V are my labels; the lecture just says "a
  second linear term on the previous hidden state."*

Tiny example (verified, tanh, x = 1, h(t-1) = 0.5, W = 0.8, U = 0.4,
b = 0): h(t) = tanh(0.8 + 0.2) = tanh(1.0) = **0.762.**

### Unrolled view
x1 -> h1 -> y1; (x2 **and h1**) -> h2 -> y2; (x3 **and h2**) -> h3
-> y3...
- y3 depends on **x1, x2, x3** (history carried by h).
- **One-way street:** y4 does **not** depend on x5, x6... (no
  future).

## 3) The problem: vanishing gradient again
Going back in time = **nesting** more transformations (sigmoid /
tanh), exactly like the earlier vanishing gradient. The first time
steps get almost no gradient -> plain RNNs struggle with
**long-term dependencies.**
**ReLU does not save the day here** ("neural networks sometimes
match your intuition, but they sometimes don't").

## 4) GRU (Gated Recurrent Unit)
Same inputs (x(t), h(t-1)), different way to compute h(t), with two
gates, both **sigmoid** (so between 0 and 1):
| Gate | Name | Job |
|---|---|---|
| **z(t)** | **Update gate** | new info or old memory? |
| **r(t)** | **Reset gate** | which parts of the old state matter |

**h(t) = (1 - z) x h(t-1) + z x h~(t)**
- **h~(t)** = a simple-RNN-style candidate, but using
  **r(t) x h(t-1)** (element-wise).
- **z near 1 -> mostly the new candidate; z near 0 -> mostly the
  old memory.**

Worked blend (verified, h(t-1) = 1, candidate h~ = 0):
| z | h(t) |
|---|---|
| 0.2 | 0.8 x 1 + 0.2 x 0 = **0.8** (keeps memory) |
| 0.9 | 0.1 x 1 + 0.9 x 0 = **0.1** (takes new) |

**Reset gate example:** a cereal review ("amazing, perfectly
balanced breakfast, will definitely be buying again"). A plain RNN
treats the **whole text equally** and the signal washes out. A GRU
**highlights the important words** and passes them on.

**Hook:** gates = a **mixing board:** sliders decide how much
old and new to let through.

## 5) LSTM
Older cousin of GRU, **same idea.** Only difference: **two states**
(a **hidden state** and a **cell state**), so more complex math.

## 6) Reading computational graphs
A **flow-of-information diagram** (key for reading papers).
- Simple RNN: x(t) and h(t-1) -> **tanh** -> h(t).
- GRU: x(t), h(t-1) -> **sigmoid** -> z(t); same -> **sigmoid** ->
  r(t); r x h(t-1) with x(t) -> **tanh** -> h~; then
  **(1 - z) x h(t-1) + z x h~ = h(t).**
- Trace each arrow: "clear as mud" at first.

## 7) Where RNNs stand today
- **Transformers** have largely **superseded** GRU/LSTM: **highly
  parallelizable, scalable,** longer-range dependencies, better
  representations.
- GRU/LSTM still used where **low resource overhead** matters
  (**edge devices:** phones, IoT) and they have a good "inherent
  sense of time" for **numerical time series.**
- Why learn them: the principle "**how to pass information from
  one time step to the next**" is the foundation for transformers.

## Big picture recap
- Sequence data = order matters; shape **N x T x D;** pad to equal
  length.
- RNN = hidden state feeds the next step.
- Plain RNN **forgets** (vanishing gradient).
- **GRU/LSTM** use gates to keep what matters.
- Transformers are the modern default.

# LAYER 2: QUIZ REFERENCE

- **Sequence data:** order matters; examples: language, audio,
  time series (anti-diabetic drug sales in Australia).
- **N x T x D:** N samples, T time steps, D features. Examples:
  commute trips (latitude/longitude), stock windows (10-day boxes).
- **Padding** sequences with zeros/null for equal length.
- Inspiration: CNN compresses and keeps the important features;
  for sequences, **past values** are the important features.
- RNN: **h(t) = f(x(t), h(t-1)),** start with random h0; y(t) from
  h(t). **Unidirectional:** no future dependencies.
- Vanishing gradient hurts **long-term dependencies;** ReLU
  doesn't fix it for sequences.
- **GRU = gated recurrent unit;** gates: **update z(t)** and
  **reset r(t)** (both sigmoid, 0-1).
- z: **take new or keep previous;** z near 0 remembers previous,
  near 1 takes new.
- r: **element-wise** on previous state, decides what to
  **remember and forget.**
- **LSTM** (long short-term memory): like GRU but **hidden state +
  cell state.**
- **Computational graph:** flow-of-information diagram.
- Transformers: **parallelizable, scalable,** longer dependencies.
  GRU/LSTM: **lower resource overhead,** edge devices, time series.
