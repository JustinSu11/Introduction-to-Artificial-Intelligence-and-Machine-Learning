# 6.3 Convolutional Neural Networks
*AAI-501 · Week 6 · cross-checked against the transcript*

**One line:** A **CNN** reads images in **two stages:** (1) a
**feature identifier** (convolution + pooling, repeated) and (2) a
regular **dense classifier.** It finds **what** is in the image,
not **where.**

**Where it fits:** 6.2 covered dense networks. CNNs are the
image specialists.

---
# LAYER 1: LEARN IT

## The big idea
Humans don't see pixels, we see **features** (wheels, petals,
noses). CNNs build features the same way: small **filters slide
over the image** to spot patterns, then **pooling** keeps only
"found it."

**Hook:** a **stamp-sized magnifying glass** slid across a photo.
Each stamp (kernel) lights up only where its pattern appears.

## 1) Convolution = feature detector
- **Kernel** (= **feature detector** = **filter**) is a small 2-D
  grid of numbers.
- Slide it across the image. At each spot: **multiply
  element-by-element, then sum.**
- The result grid is a **feature map** (= convolved feature).
- Vertical-edge kernel -> highlights vertical lines. Horizontal
  kernel -> horizontal lines.
- **In a real CNN the network learns the kernel values itself.**
  Edge filters are just teaching examples.

### Worked example (verified)
Image (4x4) and a 2x2 kernel [[1, 0], [0, -1]]:
```
image          kernel     feature map (3x3)
1 0 2 1        1  0       -2 -1  2
0 3 1 0        0 -1       -1  3 -3
2 1 0 4                    2  0 -2
1 0 1 2
```
First cell: 1x1 + 0x0 + 0x0 + 3x(-1) = **-2.** Big numbers =
"this pattern is here."

### Output size (valid convolution, stride 1)
**Input N x N, filter F x F -> output (N - F + 1) x (N - F + 1).**
4x4 with 2x2 -> 3x3 (matches).

## 2) Padding and stride
- **Problem:** corner pixels are covered by the kernel **only
  once;** center pixels many times.
- **Padding:** add a border of **zeros** so edges get "more at
  bats." Padding that keeps the size is **same convolution.**
  No padding = **valid convolution** (shrinks).
- **Stride** = how many pixels the kernel jumps (default 1).
  **Stride 2** gives a smaller output, acting like convolution
  **and** pooling at once ("strided convolution").
- *My addition: for an odd F, padding p = (F - 1)/2 keeps the size
  (e.g. 3x3 kernel, pad 1).*

## 3) Color images and many filters
- RGB image = **3 channels.** The kernel needs **3 layers too.**
  A 3x3 kernel over RGB = **3x3x3 = 27 numbers** multiplied and
  summed, still giving **one 2-D map.**
- Use **many filters:** each makes one feature map; stack them.
  Vertical + horizontal + 45-degree = output **4x4x3.**
- You choose the **number** of filters (10, 20, 64...), not what
  they detect.

## 4) Pooling (max pooling)
**Problem:** we care that a feature **exists,** not exactly where.
- Slide a **2x2 window, stride 2, no overlap** (**pool size 2**).
- Keep the **max** in each window.

Verified example (4x4 -> 2x2):
```
1 9 | 2 0
3 4 | 1 2          9  2
----+----    ->    6  3
0 6 | 3 1
5 2 | 0 3
```
- The "9" survives no matter where it sits in its window.
- Result: **robust feature recognition** (lecturer: "translational
  invariance").

**Trap:** pooling gives **small-shift** tolerance, not true
rotation tolerance (see slip note).

## 5) Hierarchy and the shrink-vs-grow trade
Repeat **conv -> pool** several times:
1. Layer 1: **lines, circles.**
2. Layer 2: **noses, eyes, mouths.**
3. Layer 3: **faces** (and e.g. "Tom Hanks" detector).
- Image width/height **shrink** each round, but **feature maps
  grow:** typical **32 -> 64 -> 128 -> 128.**
- "We're trading **spatial information** for **feature
  information.**"
- Why more maps deeper? Few basic shapes, many ways to combine
  them.

## 6) CNN design choices
- **Number of feature maps** per layer (usually increasing).
- **Filter size,** held constant: **3x3, 5x5, 7x7** common.
- How many conv-pool rounds.
- Usual deep learning settings: learning rate, hidden layers,
  units, **dropout.**
- **Strided convolution** as an alternative to pooling.

## 7) Stage two: flatten into the classifier
A dense network needs a **1-D** vector, but stage one outputs a
3-D box.
| Option | How | Catch |
|---|---|---|
| **Flatten** | squash it: 4x4x100 -> **1,600** | different image size breaks it: 8x8x100 -> **6,400** (doesn't fit) -> **all images must be the same size** |
| **Global max pooling** | take the **max of each feature map** -> **1x1xC** (C maps -> vector of C) | **handles any image size** |

## Big picture recap
- CNN = **conv + pool (find features) -> dense (decide).**
- Convolution: slide kernel, multiply-sum -> feature map.
- Padding/stride control size. Pooling keeps "it's here."
- Deeper = more abstract features, **smaller image, more maps.**
- Flatten (fixed size) or **global max pooling** (any size).

# LAYER 2: QUIZ REFERENCE

- CNN two stages: **feature identifier** (conv, pool) and
  **classifier** (dense).
- Convolution "is a feature detector." Terms: **kernel = feature
  detector = filter;** output = **feature map / convolved
  feature.**
- Convolution = slide kernel, **element-wise multiplication, sum.**
- **Valid convolution** output **N - F + 1.** **Stride** = pixel
  step size.
- **Same convolution** via **padding** with zeros; padding
  gives edge pixels more overlaps.
- **Multiple channels** (RGB): one kernel layer per channel; 3x3x3
  = **27** numbers.
- **Multiple filters** -> stacked output (3 filters -> 4x4x3).
- **Pooling:** pool size 2, stride 2 non-overlapping; **max
  pooling** (example maxima **9, 2, 6, 3**).
- Pooling gives **"robust feature recognition through
  translational invariance."**
- Highest value in a feature map = **best-matching location.**
- Hierarchy: lines/circles -> noses/eyes/mouths -> faces.
- **Feature maps increase** (32, 64, 128, 128) while spatial size
  shrinks.
- **Strided convolution** can replace pooling.
- **Flatten:** 4x4x100 = 1,600; needs same image size.
- **Global max pooling:** 1x1xC, handles different image sizes.
- Typical filter sizes: 3x3, 5x5, 7x7.

5. What does max pooling keep and why?
6. Why do CNNs add more feature maps as the image shrinks?

## Answers
1. Feature identifier (conv + pool) then dense classifier.
2. Kernel: small learnable grid; feature map: output of applying
   it; stride: step size; padding: zero border.
3. 28 - 5 + 1 = **24 x 24.**
4. 3 x 3 x 3 channels = 27.
5. The max in each window: "it's there," location doesn't
   matter.
6. Trade spatial info for feature info; deeper features are more
   varied.
7. Global max pooling.
8. Kernel covers them only once, so their info is under-used.
9. Network couldn't discover better, task-specific features.
