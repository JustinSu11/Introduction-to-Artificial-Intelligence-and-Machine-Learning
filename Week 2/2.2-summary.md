# 2.2 Uninformed Search
*AAI-501 · Week 2*

**One line:** Uninformed search knows **nothing** about the
solution. The algorithms differ only in **how they expand
the frontier.**

**Algorithms:** BFS, DFS, Iterative deepening, LCFS.

## Setup used in all examples
- Canonical directed graph: **start at A, goal is G.**
- **Branching factor (b):** average number of children
  per node (lines coming out of a node). Bigger b =
  bigger graph.
- **Tree depth (d):** how deep the tree goes.
- Judged on: **completeness, time, memory, optimality.**

---

## 1. Breadth-first search (BFS)
**How:** search **level by level.** Finish one level
before the next. Root = start node.

**Frontier on the canonical graph:**
- A
- AB, AC, AD (1 step)
- ABE, ABF, ACJ, ADH (2 steps)
- ABE dropped (terminal node, goes nowhere). Next:
  ABFD, ACJG, ADHG (3 steps) -> **ACJG found the goal.**

| Criterion | Result |
|---|---|
| Complete? | **Yes** |
| Time | **Exponential** |
| Memory | **Exponential** (frontier gets huge) |
| Optimal? | **Yes only if every step costs the same.** It finds the **fewest arcs (steps)**, not lowest cost. |

**Optimality caveat:** with different costs (e.g., 5 vs
8), fewest steps does not mean lowest cost.

**Use when:** small problems where you need the **fewest
steps** (it eventually runs out of memory).
**Applications:** social network analysis, web crawling.

---

## 2. Depth-first search (DFS)
**How:** follow **one path all the way to its end**, then
back up and try again. No sidetracks.

**Canonical graph:** A -> AB -> (ABE is a dead end) ->
ABF -> ABFD -> ABFDH -> ABFDHG = **goal found.**
Frontier stays **much smaller.** (Lucky in this example.)

| Criterion | Result |
|---|---|
| Complete? | **No.** Can get stuck on an **infinitely long path.** One counterexample is enough. |
| Time | **Exponential** |
| Memory | **Linear** (only tracks the node in front of it) |
| Optimal? | **No.** May find a deep solution while a shallower one exists. |

**Use when:** larger problems, **limited memory**, many
possible solutions and you just need **one**.
**Applications:** file system traversal, code analysis.

---

## 3. Iterative deepening
**How:** run **DFS to a set depth**, then **start over**
with the next deeper depth (depth 0, 1, 2, 3...).
Same exploration order as BFS, but computed with DFS
(backtracking instead of holding all nodes in memory).

**Canonical graph:**
- Depth 1: AB, AC, AD
- Depth 2: ABE, ABF, ACJ, ADH (ABE trimmed, dead end)
- Depth 3: ABFD, ACJG, ADHG -> **found.**

| Criterion | Result |
|---|---|
| Complete? | **Yes** (searches level by level) |
| Time | **Exponential** |
| Memory | **Linear** (gets DFS's small-frontier benefit) |
| Optimal? | Same as BFS: **fewest arcs.** Optimal only if unweighted / all costs equal. |

**Use when:** **limited memory** and you want the
**fewest steps.**
**Applications:** **game tree search** (chess, checkers),
robot navigation.

---

## 4. Lowest-cost-first search (LCFS)
**How:** always expand the path with the **lowest running
(total) cost so far.** The first strategy that uses
**edge costs.**

**Walkthrough (costs):** A->B = 2, A->C = 3, A->D = 4.
Expand the cheapest total first. Order by total path
cost: 4, then 5, then 6, then 8...
- AB = 2 (expand first), then ABE = 4, ABF = 5.
- Not ABFD next: AC (3) and AD (4) are cheaper than
  ABFD (7), so expand those first.
- ACJ = 10 later.

| Criterion | Result |
|---|---|
| Complete? | **Yes** |
| Time | **Exponential** |
| Memory | **Exponential** |
| Optimal? | **Yes** (with weighted edges, finds lowest total cost) |

**Use when:** you need the **lowest total path cost.**
**Applications:** **GPS navigation, delivery planning.**

---

## Comparison table
| Strategy | Complete | Time | Memory | Optimal | Best for |
|---|---|---|---|---|---|
| **BFS** | Yes | Exponential | Exponential | Yes (equal costs / fewest arcs) | Small problems, fewest steps |
| **DFS** | **No** | Exponential | **Linear** | **No** | Large problems, low memory, any solution |
| **Iterative deepening** | Yes | Exponential | **Linear** | Yes (fewest arcs / unweighted) | Low memory + fewest steps |
| **LCFS** | Yes | Exponential | Exponential | **Yes (lowest cost)** | Lowest total cost |

## Application summary
| Strategy | Where it's used |
|---|---|
| BFS | Social network analysis, web crawling |
| DFS | File system traversal, code analysis |
| Iterative deepening | Game tree search (chess, checkers), robot navigation |
| LCFS | GPS navigation, delivery planning |

## Quick-check list
- Which are complete? (all except DFS)
- Which have linear memory? (DFS, iterative deepening)
- Which is the only one optimal for weighted costs?
  (LCFS)
- Why is BFS "optimal" only sometimes? (counts steps,
  not cost)
- Why isn't DFS complete? (infinite paths)
- What's a branching factor? Tree depth?
