# 2.3 Informed Search
*AAI-501 · Week 2*

**One line:** Informed search uses a **heuristic** (an
estimate of how close we are to the goal) to search more
effectively.

**Algorithms:** Greedy best-first, A*, Depth-first branch
and bound.

## Heuristic
- A **heuristic** = an **estimate of the cost from the
  current state to the goal.**
- Easier to create than you'd think.
- **Example:** walking from the San Diego Farmer's Market
  to the Civic Theater in a grid-layout downtown. Use
  **straight-line ("as the crow flies") distance.** It's
  shorter than the real route, but a good estimate.
- Another example: robotic arm, distance from hand to the
  ball it wants to grasp.

## Admissible heuristic
- **Always less than or equal to the actual cost to the
  goal** (never overestimates).
- **Every informed algorithm in this lecture needs one.**
- Straight-line distance works on a grid because real
  routes are always longer.

**How to create one:** **solve a simpler (less
constrained) version of the problem.** The simpler
solution allows shortcuts, so it can't exceed the true
cost.

---

## 1. Greedy best-first search (GBFS)
**Goal:** minimize the heuristic **h(n)**. Always expand
the frontier node with the **lowest heuristic value**
(the one that looks closest to the goal).

**Example:** A has h = 40, goal G has h = 0. Heuristic
values drop as you approach. The algorithm picks the
lowest-h node each time: **A -> C -> F -> G.**

| Criterion | Result |
|---|---|
| Complete? | **No** (can get stuck in infinite paths or loops) |
| Time | **Exponential** (worst case) |
| Memory | **Exponential** |
| Optimal? | **No** (heuristics are an assumption, no guarantee of lowest cost) |

**Use when:** you need a **quick, good-enough** answer.
**Applications:** agents that must act fast, e.g.,
**UAV/drone** course corrections to avoid a tree.
**Real-world use:** occasionally.

---

## 2. A* search
**Goal:** minimize **cost so far + heuristic**:
**f(n) = g(n) + h(n)**
- g(n) = running cost to reach node n
- h(n) = estimated remaining cost to goal

Combines **both** pieces of info.

**Example 1 (start A, h = 7):**
- AB = 2 + 5 = **7**
- AD = 4 + 6 = **10**
- AC = 3 + 9 = **12**
- Expand AB: ABE = 2+2+3 = **7** (terminal, not an
  option), ABF = 2+3+5 = **10**
- Expand ABF: ABFD = 2+3+2+6 = **13**
- Then expand AD, then AC, and so on.

**Example 2 (S -> G):** expand lowest f each time:
S's children A, B, C; A is lowest. A's children B and D;
D (14) is next. D's children H, I, F; F is lowest (13).
F -> G (h = 0). **Total path cost = 23.**

| Criterion | Result |
|---|---|
| Complete? | **Yes** |
| Time | **Exponential** |
| Memory | **Exponential** |
| Optimal? | **Yes, if the heuristic is admissible** |

**Use when:** you need an **optimal** solution and have
**no big memory constraint.**
**Applications:** robotics, navigation, bioinformatics
(protein and molecule structures).
**Real-world use:** **very frequently.** One of the most
common informed strategies.

---

## 3. Depth-first branch and bound (DFBB)
**How:** run **DFS**, and when there are **multiple
solutions**, use the **best solution found so far as a
bound.** Prune any path longer (costlier) than the bound.

**Example:** 6 solution nodes.
- 1st solution found = **5 arcs** deep -> prune anything
  longer than 5.
- Solution 2 is 6 arcs: **not explored.**
- Solution 3 is 5 arcs: **not better**, so skipped.
- Solution 4 is **3 arcs** -> new bound = 3. Only explore
  paths of 3 arcs or shorter.
- Result: **optimal** solution found, with lots of pruning.

| Criterion | Result |
|---|---|
| Complete? | **Yes** |
| Time | **Exponential** |
| Memory | **Linear** (it's DFS-based) |
| Optimal? | **Yes** (even if it takes several rounds) |

**Use when:** you need an **optimal** solution **with some
memory constraints.**
**Applications:** **constrained optimization** (logistics,
sales, manufacturing). Example: limited sales budget, a
fixed number of plants. Covered next module.
**Real-world use:** somewhere in between.

## Informed comparison
| Strategy | Complete | Time | Memory | Optimal | Use when |
|---|---|---|---|---|---|
| **Greedy best-first** | **No** | Exponential | Exponential | **No** | Fast, good-enough |
| **A*** | Yes | Exponential | Exponential | **Yes** (admissible h) | Optimal, memory not a concern |
| **DF branch and bound** | Yes | Exponential | **Linear** | **Yes** | Optimal, memory limited |

**Frequency in practice:** Greedy = occasional.
A* = frequent. DFBB = in between.

## Master table: all 7 strategies
| Strategy | Type | Complete | Memory | Optimal |
|---|---|---|---|---|
| BFS | Uninformed | Yes | Exponential | Yes (equal cost) |
| DFS | Uninformed | **No** | Linear | **No** |
| Iterative deepening | Uninformed | Yes | Linear | Yes (equal cost) |
| LCFS | Uninformed | Yes | Exponential | **Yes** |
| Greedy best-first | Informed | **No** | Exponential | **No** |
| A* | Informed | Yes | Exponential | **Yes** (admissible) |
| DF branch and bound | Informed | Yes | Linear | **Yes** |

All 7 have **exponential time.**

## Advanced approaches
- **Backward search:** make an **inverse graph** and work
  from the **goal back to the start.**
- **Bidirectional search:** run forward and backward
  searches **at the same time** and see where they **meet
  in the middle.**
- **Island search:** split the problem into **contiguous
  chunks** and solve them **in parallel.**
  - Example: 2nd floor to 10th floor = (1) to the
    elevator, (2) elevator from floor 2 to 10, (3) from
    the elevator to the destination.
  - Helps **reduce combinatorial explosion** and limit
    the Big O impact.
