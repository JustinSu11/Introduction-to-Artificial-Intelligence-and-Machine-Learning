**One line:** Use **NetworkX** to build a weighted graph, then

## NetworkX
- "The **gold standard** for building, searching, and working
  with graphs in Python."
- **Imports:** `networkx` and `matplotlib` (to see the graphs).
  Not installed locally? `pip install networkx matplotlib`.
- **Nodes can be almost anything hashable** (lists, images...).
  Lab keeps it simple: letters.

## Build and draw a graph (functions in order)
| Step | Function | Notes |
|---|---|---|
| 1. Create | `nx.Graph()` | Empty graph |
| 2. Add nodes | `add_nodes_from([...])` | Lab: **A, B, C, D, E, F** |
| 3. Add edges | `add_weighted_edges_from([...])` | List of edges **with weights** |

| 6. Edge labels | `nx.get_edge_attributes(G, 'weight')` then `nx.draw_networkx_edge_labels(...)` | Shows the weights on edges |

- Then `plt.show()`. Result: a map with nodes and weighted edges.

## 1. Dijkstra (uninformed)
- Goal: **shortest path from A to F.**
- **Dijkstra's algorithm = an efficient implementation of
  lowest-cost-first search (LCFS)**, well known in data science
  and AI.
- Call: `nx.dijkstra_path(G, source, target, weight='weight')`
  - **source** = start node (A), **target** = end node (F)
  - **weight** = which edge attribute to optimize
- Prints the path. **Lab result: A, C, B, D, E, F.**
- Homework-ish: verify by hand that it really is the shortest.

## 2. A* (informed)
- Needs a **heuristic.** Lab uses **made-up values** (a
  dictionary of "straight-line distances"; lecturer: "I have no
  idea if this is correct, we're making things up").
  - Example: heuristic from A to F = **7**.
- **Heuristic function:** with informed search you **always
  give the algorithm a function** that returns the heuristic
  for any node. Signature takes **n1 (current node) and n2
  (goal node)**; the simple version just **looks up n1 in the
  dictionary** and returns it.
- Call: `nx.astar_path(G, source, target, heuristic=h, weight='weight')`
  - **Identical to Dijkstra** except for the extra `heuristic`
    argument.
- **Lab result: A, C, B, D, E, F** (same path as Dijkstra).

## 3. A better heuristic: Euclidean distance
- Why: a lookup table doesn't scale. In big networks you can't
  list every node, so **compute the heuristic on the fly.**
- Setup: recreate nodes A-F, but with **(x, y) positions**
  (a dict of positions). Add nodes with
  `add_nodes_from(positions.keys())`. Add the weighted edges
  and draw again; the coordinates place the nodes.
- Define `euclidean_heuristic(n1, n2)`: gets the **(x, y) of
  the current node and of the goal node**, returns the
  **Euclidean (straight-line) distance.**
- Run `astar_path` again, passing **`euclidean_heuristic`** as
  the heuristic. **This is the only change** vs the lookup-table
  version.
- **Lab result: A, B, D, F.** (This is a recreated graph, so
  the path differs from the first one.) Lecturer: check if you
  can find an even shorter path.

## Runnable sketch *(my addition, tested with NetworkX 3.7 on a
made-up graph; swap in your own nodes, weights, positions)*
```python
import math
import networkx as nx

G = nx.Graph()
G.add_nodes_from("ABCDEF")
G.add_weighted_edges_from([
    ("A", "B", 2), ("A", "C", 1), ("C", "B", 1),
    ("B", "D", 2), ("D", "E", 1), ("E", "F", 1), ("D", "F", 5),
])

path = nx.dijkstra_path(G, "A", "F", weight="weight")

pos = {"A": (0, 0), "B": (2, 0), "C": (1, 1),
       "D": (4, 0), "E": (5, 1), "F": (6, 0)}

def euclidean_heuristic(n1, n2):
    return math.dist(pos[n1], pos[n2])

path_a = nx.astar_path(G, "A", "F",
                       heuristic=euclidean_heuristic,
                       weight="weight")
print(path, path_a)
```

## Gotchas *(my additions, not in the lecture)*
- **A* is only guaranteed optimal if the heuristic is
  admissible** (never overestimates). The lab's made-up numbers
  may not be, so a wrong path is possible.
- Euclidean distance is admissible only if each edge weight is
  **at least** the straight-line distance between its nodes.
- Dijkstra needs **non-negative** weights.
