# 4.3 Tree-Based Methods II
*AAI-501 · Week 4 · cross-checked against the transcript*

**One line:** Build a tree greedily, **prune** it to stop
overfitting, then **ensemble** many trees (bagging, random forest,
boosting) to fix their weaknesses.

**Hook:** One tree = one opinion (shaky). A **forest** = a vote
(stable). **Boosting** = a relay where each runner fixes the last
runner's mistakes.

## Building a tree: 3 questions at every step
1. **Which node** to split next?
2. **Which variable** to split on?
3. **Which threshold** to use?
- Method: **try everything** and keep the choice that **reduces the
  cost function the most.**

### Cost functions
| Tree | Cost |
|---|---|
| **Regression** | **Residual sum of squares (RSS)** |
| **Classification** | Based on **purity** (e.g., **classification error E = 1 - max p-hat_mk**, where p-hat_mk = proportion of class k in node m) |
- **Purity:** a good split **increases the share of one class** in
  the new node. 50/50 -> 75/25 = more pure. Example: top class
  goes 60% -> 80%, so E goes **0.4 -> 0.2.**

### Greedy
- Make the **best split right in front of you** and keep going
  (like greedy best-first search, Module 2).
- A "worse now, better later" combination is not searched:
  **checking every sequence is computationally infeasible.**
- Keep splitting until each terminal node has **fewer than n
  observations** (you choose n).

## Overfitting and pruning
- Overfitting is **easy:** split until one leaf per observation.
  Example: 365 days of clothing data -> 365 leaves. **Fits the
  training data perfectly, fails on new data.**
- **Fix:** grow a **very deep tree**, then **prune backwards.**
- New cost: **RSS + alpha x |T|.** |T| = tree **size** (the lecture
  says "number of splits or depth"; in the textbook it's the
  number of terminal nodes). Larger alpha penalizes complexity.
  Chop leaves while the combined cost improves.
  *(The lecture says "maximize" the term; it should be
  minimize.)*

## Pros and cons of a single tree
| Pros | Cons |
|---|---|
| **Easy to interpret** (until ~500 splits) | **Lower accuracy** than linear or logistic regression |
| **Robust to outliers** and redundant variables | **Prone to overfitting** |
| **Fast** training and scoring | **Unstable:** changing 3 of 100 points can change the splits and force a retrain |
- Resolution: trees are powerful **when ensembled.**

## Ensembles
### Why averaging works
- Averaging n observations reduces variance (to **variance / n**
  in the lecture's statement).
- We don't have B training sets, so we make them with
  **bootstrapping:** **sample with replacement** from the one
  dataset.

### Bagging (bootstrap aggregating)
- Make **n bootstrapped datasets**, fit **n deep trees**, **average**
  their predictions (vote for classification).
- Grow the trees **deep**; individual variance gets washed out by
  averaging.
- Works with many algorithms, **especially trees.**

### Random forest
- Bagging **plus:** at **each split**, the tree may only consider a
  **random subset of features** (e.g., **5 of 25**).
- **Why:** with one very strong predictor (the "answer key"),
  every bagged tree picks it first, so the trees look alike and are
  **highly correlated** -> little variance reduction. Hiding it
  from some splits **decorrelates** the trees and forces more
  robust learning.

### Out-of-bag (OOB) error
- Each bootstrap sample leaves out data; on average a tree uses
  only about **2/3** of the data.
- For each point, vote using only trees that **never saw it.**
  That gives a **built-in test estimate** with no separate test set.
- Example: Tree 1 saw A,B,D (not C,E); Tree 2 saw A,C,D,E (not B);
  Tree 3 saw A,B,E (not C,D). For B, only Tree 2 is allowed.
  For C, Trees 1 and 3 vote.

### Variable importance
- Average each feature's **improvement** (drop in RSS or gain in
  purity) **across all trees**, then **normalize** so the top
  feature = **100.**
- Example: purity changes 0.2, 0.1, 0.5 -> average.

### Boosting
- **No bootstrapping; one dataset, trees built in sequence.**
- Fit a **weak** tree -> compute **residuals** (what it got wrong)
  -> fit the next tree **on those residuals** -> repeat. Each tree
  fixes the previous errors.
- **lambda** weights how much of each tree's residual fit is
  used (1 = full, 0 = none). Combined weak trees = **strong
  classifier.**

| | Random forest | Boosted trees |
|---|---|---|
| Overfitting risk | **Lower** | **Higher** |
| Accuracy | Good by default | **Usually better** |
| Tuning | **Less** | **More** |
| Training speed | **Faster** | Slower |

### Boosting variants
**XGBoost, CatBoost, AdaBoost, NGBoost:** all are boosted trees
with different tricks. **XGBoost** tricks: **regularization**
(penalizes complex trees), uses **first AND second derivatives**
for faster convergence, handles **sparse data** well, parallelized,
faster and more scalable. Try several.
