# 4.1 Supervised Learning: Model Building
*AAI-501 · Week 4 · cross-checked against the transcript*

**One line:** Building a model = **minimizing a differentiable loss
function** by **gradient descent**, judged on **held-out data**,
while balancing **bias vs variance**.

**Hook:** Walk down a foggy mountain by always stepping in the
steepest downhill direction. Step too small = never arrive.
Step too big = overshoot the valley.

## Why linear regression still matters (4 reasons)
Model: **Y = B0 + B1 X** (intercept + coefficient). Fit it from
observations; **residuals** = actual minus prediction.
1. **Interpretability:** coefficients show impact and relative
   importance (e.g., ROI per dollar of Instagram ads).
2. **Statistical inference:** p-values and **confidence intervals**.
3. **More powerful than people think:** interaction terms (x*y),
   non-linear features (x^4, log x).
4. **Computationally efficient:** easy to deploy, debug, scale.

**Business example (Pinterest ads):** each $1 returns **$3.50**,
95% CI **$3.25 to $3.75**, board needs ROI **at least $3.**
What matters is the **lower bound ($3.25) is above $3**, not
whether the point estimate is exactly 3.50. Inference answers
"is it above my decision threshold?"

**Linear does not mean linear everywhere:**
- **Log-transformed model:** model log(y) (house prices, demand
  elasticity).
- **Polynomial regression** (e.g., car stopping distance).
- **GLMs** (generalized linear models): dependent variable need
  not be normal.
- **GAMs** (generalized additive models): smooth non-linear
  functions of predictors.

## How do we find B0 and B1?
- Idea: try many (B0, B1) lines, keep the one with the lowest
  error (e.g., **MSE**).
- Goal: **minimize the error/loss function.**
- **Catch:** for efficient search, the loss must be
  **differentiable.**

## Gradient descent
- Rewrite the loss as a **function of the parameters** (substitute
  y-hat = B0 + B1 x; y_i and x_i are just data).
- The **minimum** is where the slope (derivative) is **0.** In many
  dimensions the derivative becomes the **gradient** (the partial
  derivative for each parameter).
- Usually you **can't solve gradient = 0 directly** (too many
  parameters), so you **iterate.**
- **Steps:**
  1. Start at a **random** parameter value.
  2. Compute the **gradient** (steepest direction) at that point.
  3. Update: **new = old - alpha x gradient.**
  4. Repeat until it **converges** to a minimum.
- **alpha = learning rate** (step size).

### Learning rate
| Too small | Too large | Just right |
|---|---|---|
| Takes very long to converge | **Overshoots**, loss can **spike up** | Steady descent |
- Too high can also **plateau quickly at a worse loss.**
- Found by **trial and error**; watch the **loss curve** over steps.

## Loss function vs performance metric
- Both measure how well predictions match truth.
- A loss function **must be differentiable.**
- **MSE** works as both for regression.
- **Binary classification loss: binary cross-entropy.**
  - If truth = 1, loss reduces to **-log(y-hat)**: -log(1) = 0
    (good), -log(0) = huge (bad).
  - If truth = 0, loss reduces to **-log(1 - y-hat)**: same logic
    reversed.
  - So it punishes confident wrong answers.
- Metrics like accuracy or F1 are **not** differentiable, so they
  are used to evaluate, not to train.

## 3 flavors of gradient descent
| Type | Data per update | Pros | Cons |
|---|---|---|---|
| **Batch** | **All n** samples | Smooth, repeatable (deterministic) | Slow on big data, can stick in local minima. Best for small data |
| **Stochastic (SGD)** | **1** sample | Fast per step, randomness helps escape minima. Good for **large data** and **online learning** (streaming, e.g., stock ticks) | Noisy convergence |
| **Mini-batch** | **32, 64, 128...** | Balances both, uses parallelism. **Default in deep learning** | Adds a hyperparameter (batch size) |

## Optimizers (smoothing and scaling the steps)
| Method | Idea |
|---|---|
| **Momentum** | Keeps a **velocity** = moving average of past gradients (e.g., 90% new, 10% old). Smooths SGD/mini-batch bouncing |
| **RMSprop** (root mean square prop) | Divides the gradient by a **running average of squared gradients.** Big gradients get **smaller** steps, small gradients get **bigger** steps. Prevents oscillation, exploding or vanishing steps |
| **Adam** | **Momentum + RMSprop.** Most common optimizer in deep learning, usually outperforms others |
- Problem solved: gradients of very different sizes per
  parameter (e.g., thousands for B0, ones for B1) cause
  oscillation.

## Train/test split
- Split data into **training** (fit by gradient descent) and
  **test** (judge only).
- Why: fitting on everything is like **giving the robot the
  answer key.** You score 100 by memorizing without learning the
  math. Practice questions = train, held-back exam = test.
- ML goal: learn the **function that generated the data**, not
  memorize the data.
- Loop: train with hyperparameters (learning rate, momentum,
  Adam values) -> test -> retrain.
- **Downsides:** repeated peeking biases you toward the test set,
  and holding out 20-30% wastes expensive data.

## Cross-validation (k-fold)
- Split into **5 equal folds (20% each).** Train on 4, test on 1.
  **Rotate** so every fold gets a turn as test. **Average** the
  scores.
- **Pros:** uses all the data, more reliable estimate.
- **Cons:** **more compute** (5 runs), more complexity,
  **data leakage** risk if you don't **randomize** before
  splitting (like grouped with like).

## Going to production
- After tuning with train/test or CV, **train the final model on
  ALL the data.** (A common practitioner mistake is deploying the
  70% model.)

## Bias and variance
**Arrow-shooting target:**
- **Bias** = how far from the bullseye (accuracy). **Low bias =
  shots near the center.**
- **Variance** = how spread out the shots are. **Low variance =
  tightly grouped.**

**In ML:** the training set is a **sample** from a population.
Example: blood pressure model, ~300M people in the US, training
sets of **10,000** records from different regions.
| | Meaning | Cause |
|---|---|---|
| **High bias (underfit)** | Model **too simple** to capture the pattern. Misses no matter which sample you use. Example: linear model on logarithmic data | **Too few parameters** |
| **High variance (overfit)** | Model **too complex**, fits the **noise** of one sample. Models differ wildly across samples | **Too many parameters** |
- Goal: **low bias AND low variance.** A trade-off in
  **model complexity** (find the sweet spot).

### How to diagnose
| Tool | High bias | High variance |
|---|---|---|
| **Learning curve** (train vs CV score as data grows) | **Both scores poor** even with more data | **Great training score, low CV score, a gap** |
| **Good fit** | Training and CV scores **converge to a high value** | |
| **Cross-validation errors** | High errors **across all folds** | Errors **differ across folds** |
| **Complexity test** | Increasing complexity **helps** | Decreasing complexity **helps** |
| **Residuals** | **Systematic pattern** | **Large scatter** |
| **Decision boundary** | Too simple | Too complex and fragmented |
